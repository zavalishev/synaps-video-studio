# beat-planner — раскадровка от звука

## Карточка

**Зачем**: раскадровка от голоса — `beats.json` (биты по словам из words.json), склейки на
границах слов, крупность и композиция каждого бита. После `studio voice`, до сцен.

**Команды**: `npx tsx .claude/skills/beat-planner/beats.ts words | suggest --pace explain|story|hook|mixed [--keep "фраза"] | check`
(check печатает `--cuts` для probe). В сцене: `<Beats beats render/>`, `beatAt`, `beatProgress`,
`cutsOf` из `@studio/beat-planner`.

**Поля бита**: `id, from, to, text, kind, shot, composition, hero, keywords, why, claim`.
- `claim` (по желанию) — что бит утверждает картинкой и текстом и откуда: «8 мест → бриф
  «мест всего 8»» / «данные: tmax» / «образ». Без источника — вопрос заказчику.
- `kind: "hook"` — первый бит: почему не пролистают (в `why`); кадр 0 показывает боль или
  обещание аудитории без звука (брекеты в отражении, а не нейтральный портрет); `"payoff"` + `hero` — развязка,
  самый плотный момент; `"establish"` — нарочный общий план без героя (review не ругается).
- `shot` и `composition` — открытый словарь, решаешь ты: общий / средний / деталь; шрифт во
  весь кадр, предмет во весь кадр, сверху, через плечо, не по центру (треть), разделённый кадр.
  Три бита подряд с одинаковой крупностью и местом героя — слайд-шоу (review: `same-shot`).

**Словарь склеек** (живо, но без вжухов): склейка на слове; по форме (круг → круг); по действию
(рука ставит чашку → та же чашка на другом столе); на долю музыки; текст как переход (слово
закрывает кадр); «влёт» в деталь; резкая склейка на цену/цифру.

**Списки** (вакансия, условия, прайс, «5 причин»): список — содержание, не форма. Варианты:
мелкие пункты быстрой серией (2–3 за 1.5 с) + долгий план и удар на главном; «смена/день
изнутри»; «вопрос зрителя → ответ». «По пункту на карточку равной длины» — review
`list-slideshow`. **Объяснение одного предмета** — живая диаграмма: каждое названное число —
действие предмета (слой едет, подпись щёлкает, камера к части, полосы перегруппировываются),
одна шкала мира на весь ролик, крупность — камерой. **Крючок объяснения**: интуиция зрителя,
которую ролик опровергнет («думаешь, 20 000?»), на экране в первые 2 с — вариант, не правило.
Граница бита без склейки (камера продолжает) — `"cut": "none"` (review не ждёт смены кадра).

**Без речи** (озвучки нет — `studio doctor`, или ролик музыкальный): `durationInFrames` в job.json
задаёшь сам, биты — по событиям кадра и долям музыки (доля = 60/bpm с, если bpm в каталоге известен);
`beats.json` пишешь сам (тот же формат), `beats.ts check` работает и без words.json. Текст бита на
экране читается за его длину (≈ 3 слова/с) — иначе бит длиннее.

**Ловушки**: бит открывается в середине действия, а не стоп-кадром «исходная поза» (review
`stale-open`); на склейке предмет уже в кадре (не склейка в пустоту); короткие биты < 18 кадров
— только `kind: "punch"`; > 2 склеек в секунду — мельтешение; первые 10 с — не дольше 2–2.5 с
без перемены (probe `slow-open`).

## Подробности (читать по нужде: `studio skill beat-planner --section <раздел>`)

Ритм ролика задаёт речь, а не таймер. Бит — отрезок, в котором кадр показывает одну мысль.
Склейка — только на границе слова (лучше — фразы), картинка меняется за 1 кадр до слова.
Структура (сколько битов, где поворот) — решение директора под бриф: здесь нет обязательной
драматургии «хук → проблема → решение → CTA». Но при любой структуре три бита — решения,
а не случайность:

- **первый** (0–2 с): что зритель получает или какое напряжение видит — и почему не
  пролистает, даже без звука. Это не «заголовок-настроение»: герой/продукт/цифра уже в кадре
  0, что-то уже движется. Запиши в `why` первого бита, чем он держит;
- **развязка** (`kind: "payoff"`, поле `hero` — data-id главного предмета): самый крупный и
  самый энергичный момент — ближе план, больше масштаб, звук; review меряет, какую долю
  кадра герой занимает на этом бите;
- **последний**: итог одним взглядом (для промо: что + когда + где + бренд; для объяснения —
  вывод), призыв или петля к кадру 0 — или записанное «ничего, потому что…». Последний кадр
  может держаться после голоса (`tailSec`), если он несёт итог.

## Когда брать / когда нет

- Брать: есть `public/words.json` (после `studio voice`) и больше одной мысли в ролике.
- Без речи (музыкальный, демо интерфейса) — биты по событиям/долям музыки, формат тот же.
- Один непрерывный дубль (диорама с орбитой) — один бит на весь ролик, а внутри —
  ключевые моменты (`beats.json` всё равно полезен для звука и подписей).

## Что получается

`beats.json` в корне ролика:
```json
{ "fps": 30, "totalFrames": 441, "beats": [
  { "id": "b01", "from": 0, "to": 85, "text": "Аренда у метро дороже",
    "kind": "hook", "shot": "medium", "skill": "kinetic-typography",
    "keywords": ["дороже"], "why": "Крючок: дорогая точка и противоречие в заголовке." },
  { "id": "b02", "from": 85, "to": 159, "kind": "turn", "…": "…" } ] }
```
`from`/`to` — кадры (to не включительно, следующий бит начинается с `to`); `kind`, `shot`,
`skill` — свои слова директора; `why` — одна фраза; `transition` — по нужде
(`{ "type": "fade", "frames": 10 }`, по умолчанию склейка). Этот же файл читают сцены,
подписи (ключевые слова), звук (кадры событий) и самопроверка (запланированные склейки).

## Как

1. Посмотреть тайминги: `npx tsx .claude/skills/beat-planner/beats.ts words` (кадр начала/конца
   каждого слова, номер реплики).
2. Черновик нарезки (НЕ финал — beats.json не перезаписывается):
   ```bash
   npx tsx .claude/skills/beat-planner/beats.ts suggest --pace explain --keep "в десять раз,прибыль выше"
   ```
   Режет на сильных границах (конец фразы, пауза, запятая, граница реплики), длины около
   цели темпа; `--keep` — фразы, которые нельзя разрывать склейкой (ключевые слова);
   `--lead 1` — картинка за кадр до слова. Темпы (`--pace`, стартовые точки): story ≈ 3.6 с
   (2.4–6), explain ≈ 2.3 с (1.4–3.6), hook ≈ 1.4 с (0.7–2.2), mixed — быстрее первые 4 с.
   Свои числа: `--target 2.8 --min 1.8 --max 4.5`.
3. Директор правит черновик по смыслу: объединяет биты, где одна мысль; делит, где поворот;
   ставит `kind/shot/skill/keywords/why`; сохраняет как `beats.json`.
4. Проверка:
   ```bash
   npx tsx .claude/skills/beat-planner/beats.ts check     # FAIL — дыры/наложения/длина ≠ ролик
   ```
   Печатает таблицу битов и строку `--cuts 85,159,…` для `studio probe` (review.ts берёт её
   из beats.json сам).
5. В сцене:
   ```tsx
   import beatsFile from "../beats.json";
   import { Beats, type Beat } from "@studio/beat-planner";
   <Beats beats={beatsFile.beats as Beat[]} render={(b) => <Shot beat={b} />} />
   ```
   Каждый бит — `<Sequence>` (кадр внутри сцены — от начала бита, монтируется заранее,
   чтобы картинки успели загрузиться). `overlap` — если бит входит растворением.
   `beatAt`, `beatProgress`, `cutsOf` — по нужде.

## Ремесло

- **На склейке предмет уже в кадре.** Склейка в пустой кадр с последующим появлением читается
  как мигание. Вход «снизу/из прозрачности» — внутри бита (или только у первого), на склейке —
  максимум мягкая посадка масштаба 0.985 → 1 за 10–12 кадров.
- Один бит — одна главная вещь в кадре. Смена фона/плана — на повороте мысли, не на каждой фразе.
- Ключевая фраза не рвётся склейкой и не рвётся между страницами подписей (Captions сам
  держит фразы из `keywords` вместе).
- Короткие биты (< 18 кадров при 30 fps) — только осознанный удар (`kind: "punch"`).
  Больше двух склеек в секунду probe провалит — это и есть «мельтешит».
- **Крупность плана — на каждый бит.** Склейка на слове между общим, средним и деталью
  (пенка и корица крупно, рука, дверь) держит внимание и не «прыгает»: «прыгает» — это
  вжухи и пружины, а не смена плана на слове. Поле `shot` — не украшение: если пять битов
  подряд `wide` — это слайд-шоу; выбери крупности так, чтобы кадр обновлялся каждые 2–3 с.
- Стартовые точки (не правила): сказка — длинные биты, но смена плана на поворотах и игра
  героя внутри кадра; объяснение — карточки движутся, но цена «камера стоит» — застой
  (review: `stale`), поэтому нужен ещё наезд к ключевой строке/смена масштаба/новый предмет;
  крючок — быстрее, ритм словами, а не блюром.
- Цифры в речи и на экране совпадают; бит с цифрой держит итоговое число ≥ 1 с.
- Звук события (sound-design) ставится на кадр события внутри бита, а не на каждую склейку.

## Чеклист

- [ ] `beats.ts check` без FAIL; первый бит с 0, последний кончается на длине ролика.
- [ ] Каждая склейка — на границе слова/фразы; ни одна ключевая фраза не разорвана.
- [ ] У каждого бита есть `why`; ни одного бита «для разнообразия».
- [ ] `why` первого бита отвечает «почему не пролистают»; есть бит-развязка с `hero`; у
      последнего бита — итог/призыв/петля или записанное «ничего, потому что…».
- [ ] Крупности планов меняются: нет длинной цепочки одинаковых `shot` под речью.
- [ ] Короткие биты — только с `kind: "punch"`; ≤ 2 склеек в секунду.
- [ ] На первом кадре каждого бита главный предмет уже виден (`studio still --frames <from>`).
- [ ] review.ts/probe: склейки только запланированные (unplanned-cut = прыжок).
