# Ролик по брифу

Студия агентная: **режиссёр решает сам** — концепт, стиль, камеру, темп, инструменты. Этот скилл
только превращает просьбу в бриф, заводит папку ролика и запускает режиссёра. Руководство
режиссёра — `studio/CLAUDE.md`, скиллы ремесла — `studio/skills/` (карточки: `studio skill <имя>`).

Если текущая папка уже папка ролика (в ней есть `job.json`) — новую не заводи: ты режиссёр этого
ролика, работай по `CLAUDE.md` (он же `AGENTS.md`) рядом.

**Codex:** рендер студии запускает браузер (Chrome Headless Shell), а в песочнице Codex он не
стартует; озвучке и картинкам нужна сеть. Всё, что рендерит или ходит к провайдеру — `npm run make`,
`studio still`, `studio render`, `studio image`, `studio voice`, `self-review/review.ts`, —
запускай с выходом из песочницы (запроси разрешение у пользователя) или в сессии
`codex -s danger-full-access`.

## 1. Готовность (≈ 10 с, бесплатно)

Из корня репозитория:

```bash
test -d node_modules || echo "нужен npm run setup"
studio/bin/studio doctor
```

- Нет `node_modules`, ffmpeg или Node < 22 — предложи `npm run setup` и остановись.
- По выводу doctor скажи пользователю одной строкой, что подключено: например «голоса нет —
  будет ролик на музыке и тексте; картинки — Gemini, без прозрачного фона». Это не вопрос:
  ролик строится под то, что есть. Хочет голос или картинки — провайдер подключается в `.env`
  (образец `.env.example`, раздел «Провайдеры» в README). **Файл `.env` не читай и не печатай,
  ключи в чат не проси**: пользователь вписывает их сам.

## 2. Бриф

Запиши `jobs/<slug>.brief.md` (папка `jobs/` не попадает в git). `<slug>` — латиница, коротко,
по теме; проверь, что `jobs/<slug>` ещё нет.

```markdown
# <о чём ролик одной строкой>
Кто публикует: <бизнес / автор, подпись или @аккаунт, если назван>
Что продвигаем и зачем: <товар, событие, мысль; чего ждём от зрителя — прийти, купить, записаться>
Зритель: <кто смотрит>
Площадка: <Reels / Shorts / TikTok; по умолчанию 1080×1920>
Факты дословно: <цены, даты, адрес, условия — только то, что сказал пользователь>
Тон и пожелания: <если есть>
Материалы: <папка с logo/photos/refs/brand.json, если дали>
Допущения: <что ты предположил сам — режиссёр вынесет их в «Вопросы заказчику»>
```

Не выдумывай цифры, состав, адреса и обещания — чего нет, то режиссёр обойдёт или спросит в
«Вопросах заказчику». Уточняющий вопрос — один и короткий, и только если непонятно, **о чём**
ролик; всё остальное — допущения.

## 3. Режим

**«Сам» (по умолчанию)** — режиссёр работает без окна, два этапа с чистым контекстом (сборка →
доводка). Это дешевле и стабильнее, чем вести весь ролик в этом разговоре. Режиссёр — тот же
агент, что и ты: `--agent claude` в Claude Code, `--agent codex` в Codex. Запусти **в фоне**
(Claude Code — Bash с `run_in_background`; Codex — `nohup … &` вне песочницы), прогон идёт
10–20 минут:

```bash
npm run -s make -- --agent <claude|codex> --brief jobs/<slug>.brief.md --slug <slug> [--brand <папка>] [--author "@handle"] \
  > jobs/<slug>.result.json 2> jobs/<slug>.progress.log
```

Пока идёт — не опрашивай в цикле; при желании загляни в `tail -5 jobs/<slug>.progress.log`.
В Codex сигнала о завершении нет: скажи пользователю, что ролик собирается в фоне 10–20 минут и
что результат покажешь, когда он спросит «готово?»; тогда проверь `jobs/<slug>.result.json`
(пустой — ещё идёт, смотри хвост progress.log).
Когда закончится, прочитай `jobs/<slug>.result.json` и коротко ответь:

- где файл (`final`; при `status: needs-stage-2` это `out/candidate.mp4` — ролик собран, но
  открыты замечания `open`) и предложи открыть: `open <файл>` (macOS) / `xdg-open` (Linux);
- концепт одной фразой (`summary.concept`), минуты и стоимость (`minutes`; у Claude Code
  `costUsd` — в пересчёте на цены API, у Codex `tokens`; на подписке это расход лимита, а не
  отдельный счёт);
- **«Вопросы заказчику»** (`clientQuestions`) — списком, без пересказа всего notes.md;
- ненулевой `exitCode` или `exists: false` — что случилось, по хвосту
  `jobs/<slug>/director.log`; продолжить можно `npm run make -- --resume --slug <slug>`.

**«Вместе»** — когда пользователь хочет участвовать («давай вместе», «покажи концепты», «хочу
выбрать стиль»), а также для **правок готового ролика**. Тогда режиссёр — ты, в этом разговоре:

```bash
studio/bin/studio new <slug> --brief jobs/<slug>.brief.md [--brand <папка>] [--author "@handle"]   # для нового ролика
cd jobs/<slug>
```

1. Прочитай `studio/CLAUDE.md` целиком — это твоё руководство, дальше работай строго по нему
   (производственный цикл, планка, бюджет, границы).
2. Каждую команду студии запускай из папки ролика с инструментами в PATH:
   `cd <корень>/jobs/<slug> && PATH="<корень>/studio/bin:$PATH" studio <инструмент> …`
   (`<корень>` — абсолютный путь репозитория). Скиллы — `studio skill <имя>`, самопроверка —
   `npx tsx .claude/skills/self-review/review.ts`.
3. Показывай пользователю развилки, а не каждый шаг: три направления концепта (он выбирает),
   лист кадров после первого `studio still --sheet`, итог review и критика. Решения — в
   `notes.md`, как требует руководство.
4. Правка готового ролика: сначала `concept.md`, раздел «## Передача» в `notes.md` и сводка
   `out/review/review.md`, затем Edit в нужной сцене `src/scenes/…`, `studio still` на
   изменённых кадрах, `studio render` (звук — `studio render --audio-only`), `studio probe`.

## Границы

- Платно — только `studio voice` и `studio image` (ключи пользователя из `.env`). Видео, музыку
  и 3D по картинке не генерировать.
- Не менять `studio/` ради одного ролика: улучшения студии — предложением в `notes.md`.
- git-команды в папке ролика не нужны; ролики (`jobs/`) не коммитятся.
- Чужие логотипы, бренды, реальные люди без согласия — нельзя; регулируемые категории
  (медицина, финансы, алкоголь, дети) — режиссёр ведёт по скиллу `claims-and-compliance`.
